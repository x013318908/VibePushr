# VibePushr 仕様書（単一PHP / フォルダーUI / ファイル単位同期）

## 1. 目的 / コンセプト

バイブコーディングの成果物を「最速で公開」するための **フォルダー単位の同期ツール**。
ホスティングの標準ファイルマネージャーとの差別化は以下：

* UIは**ファイルではなくフォルダー**を中心に扱う（操作も認知もフォルダー単位）
* 同期は内部的に**ファイル単位送信**（失敗リトライ・再開が効く）
* 転送量削減のため、**必要な場合のみ**クライアント側でgzip圧縮して送信し、サーバー側で展開して保存する
* 単一PHPファイルをアップロードするだけで動く

## 2. 非目標（Out of scope）

* ファイル一覧の表示（MVPでは表示しない）
* ファイル編集、リネーム、移動、削除
* zip/tar などのアーカイブをサーバー側で展開して一括配置（今回はやらない）
* 巨大ファイル向けのチャンク分割・結合（不要）

## 3. 対象環境 / 互換性

* サーバー：共有ホスティング想定、**単一PHPファイルで動作**
* PHP：**PHP 7.4 以上**を基準（PHP8専用機能は使わない）
* 必須拡張：`zlib`（`gzdecode()`利用）
* ルートディレクトリ：`ROOT_DIR` を固定（例：`__DIR__`）

## 4. 画面（UI）要件

### 4.1 フォルダー一覧（メイン）

* `ROOT_DIR` 配下の**全フォルダー**を一覧化（再帰）
* 表示項目：

  * フォルダー相対パス（例：`src/components`）
  * 内部ファイル数（再帰）
  * 合計サイズ（再帰、bytes）
* 表示形式：

  * 階層ツリー もしくは フラット一覧（相対パスの文字列でOK）
* ファイルは表示しない（リンクも不要）

### 4.2 同期（フォルダー選択）

* クライアント側でフォルダー選択（`<input type="file" webkitdirectory multiple>`）
* 進捗表示が最重要：

  * 総ファイル数
  * 完了数 / 失敗数
  * 現在処理中の相対パス
  * 直近エラー（必要なら数件）

## 5. 機能要件（同期）

### 5.1 同期の基本動作

* ローカルで選択したフォルダー内のファイルを列挙し、**ファイル単位**にサーバーへ送信して保存する
* 送信先は `ROOT_DIR` 配下に固定し、相対パスで配置
* 親ディレクトリが存在しない場合は自動作成する

### 5.2 送信の方式

* 1リクエスト = 1ファイル（原則）
* 送信は `fetch` を用いる
* 同時送信数は制限（推奨：2〜4）し、安定性を優先
* 失敗したファイルはリトライ可能（例：最大3回）

### 5.3 レジューム（再開）

* “巨大ファイル途中再開”は不要
* ファイル単位の再開を実現する：

  * クライアントは送信前に `stat`（存在/サイズ/mtime等）を問い合わせ、同一なら送信をスキップ可能にする（任意）
  * またはサーバー側が `sync_put` 受信時に同一判定してスキップしてもよい

### 5.4 圧縮（効く場合のみ）

* クライアント側で任意にgzip圧縮する
* gzip圧縮は以下のような基準で行う（推奨。最終判断は実装側）：

  * 拡張子がテキスト系（例：`js css html json txt md svg php`）
  * サイズが一定以上（例：8KB以上）
  * 圧縮後サイズが十分小さくなる場合のみ（例：90%未満）
* サーバー側は受信時に「gzipか否か」を判定し、gzipなら `gzdecode()` で展開して保存する
* gzip判定は以下いずれか（実装者が選択）：

  * 独自ヘッダ `X-Vibe-Encoding: gzip`
  * もしくは `Content-Encoding: gzip`（環境差があるため推奨は独自ヘッダ）

## 6. API（単一PHPのactionルーティング）

エントリポイント：`vp.php`（仮）

### 6.1 認証

* `POST action=login`

  * 入力：`password`
  * 処理：`password_verify()` で照合、成功なら session に auth フラグ
* `POST action=logout`

### 6.2 フォルダー一覧

* `GET action=list_dirs`

  * 出力（JSON推奨）：

    * `[{ path, file_count, total_bytes }]`

### 6.3 同期ジョブ

* `POST action=sync_init`

  * 入力：`total_files`, 任意で `client_id` など
  * 出力：`job_id`
* `POST action=sync_put`

  * 入力（ヘッダ/クエリ/ボディの取り決めは実装側で統一）：

    * `job_id`
    * `relpath`（必須、相対パス）
    * `mtime`（任意）
    * `encoding`（任意：`gzip` or `identity`）
    * ボディ：ファイル内容（gzipの場合はgzip済みバイト列）
  * 出力：`ok/skip/fail` とメッセージ
* `POST action=sync_finish`

  * 入力：`job_id`
  * 出力：集計（成功/失敗/スキップ件数など）
* `GET action=progress&job_id=...`

  * 出力：`done/total`, `current_path`, `errors[]` 等（ポーリング）

### 6.4 任意（スキップ判定のため）

* `POST action=stat`

  * 入力：`relpath`, `size`, `mtime`（クライアント側情報）
  * 出力：`exists`, `same_fast`（size/mtime一致など）

## 7. パス安全性（必須）

* 操作対象は `ROOT_DIR` 配下に限定
* `relpath` は以下を拒否：

  * 先頭 `/`（絶対パス）
  * `..` を含むパス（ディレクトリトラバーサル）
  * NULL byte（`"\0"`）
  * バックスラッシュ `\` は `/` に正規化するか拒否
* `resolveSafePath(relpath)` を唯一の経路として使う

  * 既存パス：`realpath()` で `ROOT_DIR` 配下を確認
  * 新規作成パス：親ディレクトリの `realpath()` を確認してから結合

## 8. 書き込みの安全性（必須）

* 受信したファイルは一時ファイルに保存後、`rename()` で原子的に置き換える
* 書き込みは `LOCK_EX` を利用（または rename による整合確保）
* 親ディレクトリ作成は `mkdir(..., true)` で再帰対応

## 9. ログ / 進捗

* job単位ログ（推奨：JSONL）

  * 例：`ROOT_DIR/.vp_jobs/{job_id}.jsonl`
  * 記録：時刻、relpath、結果（ok/skip/fail）、エラー、remote_addr
* 監査ログ（任意）：`ROOT_DIR/vp.log` に最小追記（ログイン失敗含む）

## 10. セキュリティ要件（最低ライン）

* 単一パスワードログイン（セッション）
* ログイン成功時に `session_regenerate_id(true)`
* POST系はCSRFトークン必須
* 表示の際は `htmlspecialchars` によるXSS対策
* 内部パス（絶対パス）はエラーメッセージに出さない

## 11. 受け入れ基準（Acceptance Criteria）

1. 単一PHPファイルのみで動作する
2. `ROOT_DIR` 外への読み書きができない（traversal不可）
3. フォルダー一覧に「相対パス・再帰ファイル数・合計サイズ」が表示される
4. フォルダー選択から、ファイル単位で同期（上書き更新）ができる
5. 同期の進捗（完了数/総数、現在ファイル）がUIに出る
6. gzip圧縮送信が可能で、サーバー側で `gzdecode()` 展開して保存できる
7. 失敗ファイルのみ再送（リトライ）できる（ページ内での再試行でOK）
