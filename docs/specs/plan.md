# 計画

## ドキュメント
- `README.md`、`README.en.md`、`docs/index.html`を対象に導入方法を拡充。
  - 初期状態からPHPが使えるサーバー（XREAなど）の契約が必要、と追記。
  - `vp.php`のアップロード方法か、その調べ方を追記。

## 予定（実装順）

### 1. vp.php内部ファイルの集約と非公開化
- 目的: `vp.php` が生成するファイルを1つの管理フォルダーに集約し、公開パスから直接見えない配置にする。
- 作業タスク:
  - 管理フォルダー名と配置ルールを定義する（例: 既存 `ROOT_DIR` 配下で隠しフォルダー運用）。
  - 既存の生成先（ログインガード、ジョブ状態、ジョブログ、監査ログなど）を管理フォルダー経由に統一する。
  - 既存運用からの移行方針を決める（旧ファイルが残っていても動くか、初回アクセス時に移行するか）。
- 完了条件:
  - 生成ファイルが単一フォルダー配下に集約される。
  - 既存機能（ログイン、同期、テスト実行、進捗表示）が回帰しない。

### 2. フォルダー選択UIをドロップ操作に統一
- 目的: `<input type="file">` の確認ダイアログ負担を減らし、操作感をドロップと統一する。
- 作業タスク:
  - 画面上の `input[type=file]` は非表示化し、広いドロップゾーンを追加する。
  - ドロップゾーンは「フォルダーをドロップ、またはクリックしてフォルダー選択」の挙動にする。
  - 画面全体ドロップ受付の現行挙動は維持する。
  - 選択後のファイル一覧保持・再送ボタン連携・エラーハンドリングを既存仕様と一致させる。
- 完了条件:
  - クリックとドロップのどちらでも同じ選択結果で同期可能。
  - 既存の「同期開始 / テスト実行 / 失敗のみ再送」が退行しない。

### 3. ダークモード対応（高コントラスト）
- 目的: 黒背景ベースで可読性を保ったダークテーマを追加する。
- 作業タスク:
  - 色トークン（背景、文字、罫線、強調、エラー）をテーマ変数化する。
  - ライト/ダークを切り替え可能にする（OS設定追従 + 手動切替の優先度を定義）。
  - ログ、テーブル、フォーム、ボタン、リンクのコントラストを調整する。
- 完了条件:
  - ダークモード時に主要UIの可読性が維持される。
  - 既存の機能操作に影響がない。

### 4. 未解決メモ: 誤アップロード取り消し（ロールバック）
- 課題: 直近1回のみロールバック可能な設計では、同期ボタンを短時間に2度押しした場合に、本来取り消したいジョブへ戻せなくなる。
- 必須条件:
  - ロールバック可能期間はログインロックと同じ期間（30日）にする。
  - 連続同期が発生しても、少なくとも1回はロールバック可能であることを保証する。
- 方針候補（比較検討）:
  - 30日内で N 世代のロールバック履歴を保持する。
  - 同一フォルダーの連続同期を1つのロールバック単位としてグルーピングする。
  - 同期開始前に「前回バックアップ未消化」の警告を出す。
- 位置づけ: 上記条件を満たす仕様が固まるまで、実装は保留とする。

## 実装済み
- ブルートフォース対策を実装済み。
- 前回ログインが30日以上前ならログインをロックし、`public_html/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログイン失敗回数上限（`LOGIN_MAX_FAILED_ATTEMPTS=100`）でロックし、`public_html/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログインガード状態ファイル（`.vp_login_guard.json`）の読み書きはロックを使用する。
- フォルダー一覧の文字列をリンク化し、`/対象フォルダー/` を新規タブで開けるようにした。
- 日本語ファイル名問題への対応を実装済み（解決扱い）。
  - 同期時に `relpath` と実保存先の不一致を検出し、`unicode_filename_mismatch` で fail-fast する。
  - jobログに `original_relpath` / `resolved_target` を記録して追跡可能にした。
  - サーバー依存差があるため、UI文言で「一部サーバーでは日本語ファイル名が問題になる可能性」を案内する。
- ログインURLの変更を実装済み。
  - ログイン関連操作はランダム文字列付きURLでのみ受け付ける運用とし、第三者による試行を抑制した。
  - ログインURL情報はログインガード状態とは別管理で保持する。
- MCP関連（認証フロー含む）は VibePushr 本体スコープ外として確定。
  - 本リポジトリではMCP向け仕様追加・実装を行わない。
  - 連携が必要な場合は別プロダクト側で設計・実装する。
  - 記録は `docs/specs/mcp_filemanager.md` を参照。

## 認証運用方針
- 初回起動時にセットアップ画面を表示し、管理パスワードを設定して `.vp_auth.php` へ保存する。
- 認証情報は `.vp_auth.php` のみを参照し、`vp.php` 内に固定ハッシュは持たない。
- ログイン失敗回数上限または長期間未使用でロックされた場合は、`public_html/.vp_login_guard.json` を削除して復旧する。
