# 計画

## 残タスク
- ログインURLの変更。vp.phpで誰でもログインを試行できるため、本人以外でもログイン100回試行可能になっている。これを防ぐため、初回起動時にランダムな文字列を含むログインURLを生成して、そのリンクを表示する。ログインURLでのみ、現状通りのパスワード設定やログインが可能。ログインURLはログインガード状態ファイル(.vp_login_guard.json)とは別に保存しておく。ログインURLがFTPなどで削除されていれば、次回起動時にまたログインURLを生成・画面にリンクを表示する。という案で、第三者によるシステムダウンを防げそう？
	- 以上の仕組みでログインの不正利用を防げるか検討。
- MCP実装。MCPからの認証も、ログインと同様に1人（1エージェント）だけ可能にする。FTPなどでMCP認証情報ファイルを消せば、新しいエージェントを認証可能になる。
	- MCP認証の仕組み（案）
		- エージェントから認証リクエスト、MCP認証情報がすでにできていれば拒否するが、できていなければMCP認証用のパスワードと、ランダムな文字列を含むMCP使用承認用URLを発行、そのURLとともに「このURLをユーザーに与える」という指示をエージェントに返す。ユーザーがそのMCP使用承認用URL（vp.phpへのリクエストURLでもある）にアクセスすると「承認しますか」というメッセージと「はい」ボタンがある。「はい」ボタンが押されたらエージェント（に与えたMCP認証用のパスワード）を使用可能にする。
		- 「はい」が押されるまでは何度でもエージェントからの認証リクエストを受けて、同様に反応する。
		- ユーザーと同様に、MCP認証用パスワードも30日間使われないと無効化、ロックされる。その情報もログインガード状態ファイルとは別に用意する。
		- それでも、vp.phpというファイル名であるかぎり、第三者に不正に認証される恐れはある。vp.phpのファイル名（vp部分）を変更するようユーザー向けドキュメントでおすすめ。vp.phpがリネームされていても完全に動作することを確認したい。
	- 以上の仕組みでMCPの不正利用を防げるか検討する。

## 実装済み
- ブルートフォース対策を実装済み。
- 前回ログインが30日以上前ならログインをロックし、`public_html/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログイン失敗回数上限（`LOGIN_MAX_FAILED_ATTEMPTS=100`）でロックし、`public_html/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログインガード状態ファイル（`.vp_login_guard.json`）の読み書きはロックを使用する。
- フォルダー一覧の文字列をリンク化し、`/対象フォルダー/` を新規タブで開けるようにした。

## 認証運用方針
- 初回起動時にセットアップ画面を表示し、管理パスワードを設定して `.vp_auth.php` へ保存する。
- 認証情報は `.vp_auth.php` のみを参照し、`vp.php` 内に固定ハッシュは持たない。
- ログイン失敗回数上限または長期間未使用でロックされた場合は、`public_html/.vp_login_guard.json` を削除して復旧する。
