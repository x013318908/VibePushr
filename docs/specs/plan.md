# 計画

## ドキュメント
- `README.md`、`README.en.md`、`docs/index.html`を対象に導入方法を拡充。
  - 初期状態からPHPが使えるサーバー（XREAなど）の契約が必要、と追記。
  - `vp.php`のアップロード方法か、その調べ方を追記。
  - `vp.php` のファイル名変更運用（覚えやすく十分長い任意名）を明記。
  - 認証関連の内部ファイル保存先を `.vp_data` 配下へ更新。
  - `docs/index.html` の配布バージョン表記を `v0.1.8` に更新。

## 予定（実装順）

### 1. 未解決メモ: 誤アップロード取り消し（ロールバック）
- 課題: 直近1回のみロールバック可能な設計では、同期ボタンを短時間に2度押しした場合に、本来取り消したいジョブへ戻せなくなる。
- 必須条件:
  - ロールバック可能期間はログインロックと同じ期間（30日）にする。
  - 連続同期が発生しても、少なくとも1回はロールバック可能であることを保証する。
- 方針候補（比較検討）:
  - 30日内で N 世代のロールバック履歴を保持する。
  - 同一フォルダーの連続同期を1つのロールバック単位としてグルーピングする。
  - 同期開始前に「前回バックアップ未消化」の警告を出す。
- 位置づけ: 上記条件を満たす仕様が固まるまで、実装は保留とする。

## 実装済み
- ブルートフォース対策を実装済み。
- 前回ログインが30日以上前ならログインをロックし、`public_html/.vp_data/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログイン失敗回数上限（`LOGIN_MAX_FAILED_ATTEMPTS=100`）でロックし、`public_html/.vp_data/.vp_login_guard.json` を削除するまで拒否を継続する。
- ログインガード状態ファイル（`.vp_data/.vp_login_guard.json`）の読み書きはロックを使用する。
- `vp.php` が生成する内部ファイル（認証・ログインガード・監査ログ・ジョブ情報）を `public_html/.vp_data/` 配下へ集約した。
- フォルダー一覧の文字列をリンク化し、`/対象フォルダー/` を新規タブで開けるようにした。
- フォルダー選択UIをドロップ/クリック中心に統一した。
  - `input[type=file]` は画面上では非表示化し、広い選択エリアから操作する。
  - 選択ファイル数表示を選択エリア内に統合し、未選択時は非表示にした。
  - 未選択時は「アップロード開始」「テスト実行」を無効化し、選択後に有効化する。
  - ページ全体ドロップ受付の既存挙動を維持した。
- 同期操作後にフォルダー一覧を自動再読み込みするようにした。
  - 対象: 「アップロード開始」「テスト実行」「失敗のみ再アップロード」。
- フォルダー一覧で `.始まり` フォルダーを表示するようにした。
  - 選択可能な挙動との一貫性を優先し、内部ディレクトリ（`.vp_data` / `.vp_jobs`）のみ非表示にする。
- ダークモード（高コントラスト）を実装した。
  - システム設定（`prefers-color-scheme`）に追従する。
  - テーブル、フォーム、ボタン、ログ表示のコントラストを調整。
- 日本語ファイル名問題への対応を実装済み（解決扱い）。
  - 同期時に `relpath` と実保存先の不一致を検出し、`unicode_filename_mismatch` で fail-fast する。
  - jobログに `original_relpath` / `resolved_target` を記録して追跡可能にした。
  - サーバー依存差があるため、UI文言で「一部サーバーでは日本語ファイル名が問題になる可能性」を案内する。
- ログインURL変更機能は未実装。
  - 現在は運用で `vp.php` のファイル名を任意名へ変更して公開パスを調整する方針とする。
  - 将来、アプリ内機能として扱う場合は別タスクで仕様化する。
- MCP関連（認証フロー含む）は VibePushr 本体スコープ外として確定。
  - 本リポジトリではMCP向け仕様追加・実装を行わない。
  - 連携が必要な場合は別プロダクト側で設計・実装する。
  - 記録は `docs/specs/mcp_filemanager.md` を参照。

## 認証運用方針
- 初回起動時にセットアップ画面を表示し、管理パスワードを設定して `.vp_data/.vp_auth.php` へ保存する。
- 認証情報は `.vp_data/.vp_auth.php` のみを参照し、`vp.php` 内に固定ハッシュは持たない。
- ログイン失敗回数上限または長期間未使用でロックされた場合は、`public_html/.vp_data/.vp_login_guard.json` を削除して復旧する。
