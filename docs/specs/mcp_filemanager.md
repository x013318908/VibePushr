# MCP File Manager 仕様メモ（別プロダクト）

## 方針
- MCP実装。MCPからの認証は1人（1エージェント）だけ可能にする。FTPなどでMCP認証情報ファイルを消せば、新しいエージェントを認証可能になる。
	- MCP認証の仕組み（案）
		- エージェントから認証リクエスト、MCP認証情報がすでにできていれば拒否するが、できていなければMCP認証用のパスワードと、ランダムな文字列を含むMCP使用承認用URLを発行、そのURLとともに「このURLをユーザーに与える」という指示をエージェントに返す。ユーザーがそのMCP使用承認用URL（vp.phpへのリクエストURLでもある）にアクセスすると「承認しますか」というメッセージと「はい」ボタンがある。「はい」ボタンが押されたらエージェント（に与えたMCP認証用のパスワード）を使用可能にする。
		- 「はい」が押されるまでは何度でもエージェントからの認証リクエストを受けて、同様に反応する。
		- MCP認証用パスワードは30日間使われないと無効化、ロックされる。
		- それでも、vp.phpというファイル名であるかぎり、第三者に不正に認証される恐れはある。vp.phpのファイル名（vp部分）を変更するようユーザー向けドキュメントでおすすめ。vp.phpがリネームされていても完全に動作することを確認したい。
	- 以上の仕組みでMCPの不正利用を防げるか検討する。
- MCP関連（認証フローを含む）は VibePushr 本体スコープ外として、別プロダクトで設計・実装する。
	- 本リポジトリではMCP向け仕様追加・実装は行わない。
	- 必要になった場合は、別プロダクト側の仕様・実装方針を参照して連携方法のみ検討する。
